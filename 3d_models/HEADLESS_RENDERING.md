# Headless Rendering on macOS M1 Pro

Tested: 2026-02-26
Blender: 5.0.1 (build a3db93c5b259, 2025-12-16)
System: macOS Darwin 25.2.0, Apple M1 Pro, 16GB RAM
Engine: EEVEE (required for Shader to RGB toon pipeline)

## 1. Test Results

**Mode A: `--background` works.**

EEVEE headless rendering with `--background` produces correct output on Blender 5.0.1 / macOS M1 Pro. No visible-window fallback is required.

Test render details:
- Output: 800x1200 RGBA PNG with transparent background
- Toon shade bands: present (brightness std dev 86.0)
- Freestyle outlines: present (3.8% of opaque pixels near-black)
- Render time: ~2.5 seconds for a single frame (blockout model, 64 samples)
- No crashes, hangs, or GPU context errors

This resolves the historical EEVEE headless issue (Blender bug #132664) for Apple Silicon on Blender 5.0.1.

## 2. Recommended Invocation

Phase 14's `blender-runner.ts` should use this exact command pattern:

```bash
/Applications/Blender.app/Contents/MacOS/Blender \
  3d_models/output/spyke/spyke.blend \
  --background \
  --python 3d_models/render/render_poses.py \
  -- --views <view> --poses <pose> --output <output_dir>
```

Example for a single panel render:

```bash
/Applications/Blender.app/Contents/MacOS/Blender \
  3d_models/output/spyke/spyke.blend \
  --background \
  --python 3d_models/render/render_poses.py \
  -- --views front --poses battle_ready --output output/ch-01/raw
```

The `--` separator is required to pass arguments to the Python script rather than to Blender itself.

Available `--views`: front, three_quarter, side, back, portrait, upper_body
Available `--poses`: neutral, standing_relaxed, battle_ready, drawing_katana, walking

## 3. Fallback Strategy

Since `--background` works, no fallback is needed for the current system. However, if a future macOS or Blender update breaks headless EEVEE:

**Visible window fallback:** Remove the `--background` flag. Blender will briefly open a window, render, and exit. The Python render script (`render_poses.py`) is mode-agnostic and works identically in both modes.

```bash
# Fallback: visible window (only if --background breaks)
/Applications/Blender.app/Contents/MacOS/Blender \
  3d_models/output/spyke/spyke.blend \
  --python 3d_models/render/render_poses.py \
  -- --views front --output output/ch-01/raw
```

Detection: If the subprocess exits with a non-zero code or produces a zero-byte PNG, retry without `--background`.

## 4. Transparency Guarantee

The Python render scripts are completely mode-agnostic. They call:

```python
bpy.ops.render.render(write_still=True)
```

This works identically regardless of whether Blender was launched with or without `--background`. The rendering mode is controlled entirely by the CLI invocation (presence or absence of `--background`), not by the Python script.

This means TypeScript integration (Phase 14) only needs to choose the right CLI command. No Python script modifications are needed for mode switching.

## 5. Known Issues

- **First-render warmup:** The first render in a Blender session takes ~10 seconds (GPU shader compilation). Subsequent renders in the same session take ~2.5 seconds. For batch rendering (multiple poses/views), the warmup cost is amortized.
- **Memory usage:** Blender process uses ~300-400MB for the blockout model. Refined models with higher polygon counts will use more.
- **No GPU selection:** On M1 Pro, EEVEE automatically uses the integrated GPU. No manual GPU configuration is needed.
- **Freestyle anti-aliasing:** Freestyle outline pixels are rendered with anti-aliasing, producing semi-transparent edge pixels. The validation script accounts for this by using opaque-pixel analysis (alpha > 245) rather than full-image analysis.

## 6. Output Convention: Test Renders

**Location:** `3d_models/output/spyke/test_render/`

Purpose: Validation renders produced during development and CI regression testing. These are not production outputs.

Naming: `spyke_<pose>_<view>.png` (e.g., `spyke_neutral_front.png`)

Gitignored: Yes (`3d_models/output/` is in `.gitignore`)

## 7. Output Convention: Pipeline Renders

**Location:** `output/ch-XX/raw/`

Purpose: Production renders consumed by the TypeScript pipeline for text overlay and Webtoon assembly. This is the same directory the existing pipeline expects from the generate stage.

Naming: `chNN_pNNN_vN.png` (e.g., `ch01_p003_v1.png`) -- matches existing pipeline convention. Phase 13 will add `--chapter`, `--page`, `--version` CLI arguments to `render_poses.py` for this naming.

Gitignored: No (production outputs are tracked)

## 8. Output Convention: Build Artifacts

**Location:** `3d_models/output/spyke/spyke.blend`

Purpose: The complete character model file generated by `build_spyke.py`. Contains model geometry, armature, toon shaders, cameras, lighting, and Freestyle configuration. Regenerated on demand.

Gitignored: Yes (`.blend` files and `3d_models/output/` are in `.gitignore`)

To regenerate:

```bash
/Applications/Blender.app/Contents/MacOS/Blender \
  --background \
  --python 3d_models/build_spyke.py
```
